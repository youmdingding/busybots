# Agent guidelines

Guidelines for AI coding agents (and humans) working on this repo. `CLAUDE.md` imports this file, so keep project rules here.

## What this is

An isometric pixel-art board that shows what coding agents (Claude Code, Codex CLI, Gemini CLI, OpenCode, Cursor CLI, Conductor) are doing. It runs on the user's own machine and is read-only towards those agents.

```
agent session files ──► src/watcher.js ──► status (in memory) ──► web/board/ (canvas)
  (~/.claude, ~/.codex,     │  + src/readers/*.js, src/claude.js,        ▲  GET /status.json
   ~/.gemini, opencode.db…) │    src/conductor.js                         │
                            │  + config.json (rooms, rules)               │
                            └─ settings.json (where agents live) ◄── web/admin.html, admin.js
src/server.js: serves the board files + a small localhost API (settings, agent panel)
bin/cli.js: runs watcher + server in one process (start / serve / status / doctor / service / hook)
```

| Area | Files |
|---|---|
| Watcher (classifies each session → room, bubble, badges) | `src/watcher.js` (one pass), `src/classify.js` (rules), `src/claude.js` (Claude Code transcripts), `src/conductor.js` |
| Agent readers (translate an agent's files → Claude-style events) | `src/readers/*.js`, `src/events.js`, registry in `src/readers/index.js` |
| Settings (agent folders, personal rules, board prefs) | `src/settings.js`, `web/admin.html`, `web/admin.js`; the file lives in the per-user state folder (`src/paths.js`) |
| Server + API | `src/server.js` |
| CLI, login service, Claude Code hook | `bin/cli.js`, `src/service.js`, `src/hook.js` |
| Board (vanilla JS canvas, ES modules, no build step) | `web/index.html`, `web/board/*.js` (entry `main.js`, shared state in `state.js`), `web/style.css` |
| Rooms, tool → room rules | `config.json` |
| Themes | `themes/*.json`, sprites in `tiles/`, `icons/` |
| Art generators (dev only, Python + Pillow/numpy) | `tools/city_props/*.py`, `tools/gen_assets.py`, `tools/gen_icons.py` |
| Tests | `tests/*.test.mjs`; watcher scenarios in `tests/scenarios/*.json`; visual snapshots in `tests/visual/` |

## Before you change anything

1. **Read surgically.** Read the files the task touches, not whole directories. The board is split into modules under `web/board/`: grep for the function you need.
2. **Map the blast radius.** `git grep` the callers of every function, key or file name you change, including the other side of the status-file contract: a field the watcher writes is read by `web/board/` and the server.
3. **Then implement**, with targeted edits grounded in what you read.

## Hard rules

**Read-only towards agents.** Never write, move or lock anything in an agent's folder (`~/.claude`, `~/.codex`, `~/.gemini`, OpenCode's database, `~/.cursor`, Conductor's database). Open SQLite only through `withReadOnly` in `src/sqlite.js` (read-only, and immutable when the agent isn't running so no `-wal`/`-shm` files appear). A reader that crashes must not take the board down: the watcher and the settings page already wrap each reader, so keep it that way.

**Privacy and security.**
- The board must never insert text from the status file, transcripts, folder names or settings with `innerHTML`. Use `textContent` / DOM nodes. Agent output is untrusted input.
- The server binds `127.0.0.1` only, checks Host/Origin, and serves only allow-listed board files (`STATIC_ALLOW`). New static files must be added there deliberately. Never serve dotfiles, logs, `settings.json`, the token or source files.
- Mutating API routes require the `X-Board-Token` header and must cap request size.
- No telemetry, no network calls, no external fonts or CDNs. Everything runs offline.
- Runtime data (settings, token, logs, status) lives in the per-user state folder, never in the repo. Never commit anything with a real user path in it.

**Portability.**
- Node 22.5+, **no runtime dependencies** (built-ins only: `node:sqlite`, `node:http`…). The art generators in `tools/` may use Python with Pillow/numpy.
- No hardcoded user paths: every agent location comes from settings (defaults in `src/settings.js` respect env vars like `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `XDG_DATA_HOME`). Per-user files go through `src/paths.js`.
- Must not break on Windows: use `pidAlive` / `src/proc.js` for process checks, guard `ps`/`pgrep`, build paths with `node:path`.
- Use local time, never a fixed timezone.

**Board.**
- Vanilla JS, no framework, no build step. Keep it that way unless the maintainer decides otherwise.
- One exception in a frame must not stop the animation: `frame()` already catches errors. Don't add work outside that guard in the render loop.
- Engine code should not know about a specific theme. Theme-specific things belong in `themes/*.json`.

**Art.**
- Sprites are generated by the scripts in `tools/`. Change the generator and re-run it; don't hand-edit PNGs that a script produces.
- Agent characters are original. Never draw or imitate a company's logo or a known character (Claude's starburst, OpenAI's blossom, Pac-Man ghosts, Gemini's sparkle…).

## Adding support for another agent

1. Find out exactly how the agent stores sessions: its source code if open, otherwise documented community findings. Cite file paths or URLs at the top of the reader, and say what is confirmed and what is inferred.
2. Write `src/readers/<agent>.js` exporting `discover(homes, recentMinutes)` (→ `Map` of sessions), `check(home, recentMinutes)`, `transcript(sessionId, homes)` and `defaultHome()`. Build events with the helpers in `src/events.js` (`evUser`, `evTool`, `evResult`, `evStop`…, `session()`), map tool names with `mapTool`, and read each session inside its own guard (`skipBad`) so one bad file can't hide the others.
3. Register it in `src/readers/index.js`; add defaults, `READER_SOURCES` and an `AGENT_TYPES` entry in `src/settings.js`; a character in `tools/gen_icons.py`; a filter chip in `web/index.html` and `AGENT_FILTERS` in `web/board/constants.js`.
4. Add scenarios under `tests/scenarios/` that mirror the real on-disk format (working, finished, off) and run `npm test`.
5. Update the per-agent table in `README.md`, including what the agent's files can't tell us.

## Checking your work

Tests passing is not the same as the board working.

```bash
npm test                                   # scenarios, readers, server contract, hook
node bin/cli.js doctor                     # what the board finds on your machine
node bin/cli.js status                     # one watcher pass, as JSON
node bin/cli.js serve                      # then open http://127.0.0.1:8765/?debug=1
node tests/visual/snapshots.mjs record /tmp/base   # before touching rendering…
node tests/visual/snapshots.mjs compare /tmp/base  # …after: canvas must match (needs Playwright)
```

- For any change you can see on the board, open it in a browser and look: golden path plus one edge case (no agents, many agents in one room, an agent with no name, a missing folder in Settings…). With `?debug=1`, `window.__boardDebug.frameErrors()` must stay `0`.
- Check all four themes (Island, Office, City, Space) when you touch rendering.
- Test failure paths, not just the happy path: a missing folder, a corrupt file, a reader that throws, a broken `settings.json`.
- If you can't run something (e.g. you have no Gemini install), say so plainly instead of claiming it works.
- Watcher changes must keep existing Claude Code behaviour unchanged unless that's the point of the change.

## Stop and ask

- Adding a dependency (runtime or dev).
- Changing the status-file format, the settings schema or an API route in a way that breaks existing installs.
- Architectural changes (a build step, a framework, a second runtime).
- Anything that would write outside the board's state folder.

Fix without asking: typos, obvious bugs with an obvious fix, missing imports, docs that went stale with your change.

## Never

- Mark work done that you haven't checked.
- Swallow an error silently in new code. Log it once (the watcher and server log to stderr) and carry on.
- Leave debug output, commented-out code or `.bak` files behind.

## Commits

- Small, focused commits with a message that says what changed and why.
- Keep `README.md` in step with user-visible changes (settings, agents, limits).
